# Rheed Forge-Silver House Cutscene Rework

# Part I — Product

## Overview

The Map045 Rheed cutscene appears and disappears too quickly to communicate the children's wonder. This rework gives the player a short causal beat in which the house is revealed, Rheed names it, one child physically tests the vision, another child follows that curiosity, and Rheed leads the group onward.

## Goals

- Make the Forge-Silver House the stable visual focus.
- Communicate childlike wonder without requiring audio or a second dialogue line.
- Keep the complete beat near five seconds under nominal conditions.
- Prevent fade and cleanup from clipping active speech or movement.

## User Stories

- `US-001` covers body-led wonder and perceptual focus.
- `US-002` covers deterministic completion and cleanup.
- `US-003` covers safe, replayable RPG Maker data authoring.
- [Full user stories](_user_stories.md)

## Core Features

- **Single materialization**: Animation 35 appears only on entry.
- **Body-led child reaction**: E33 steps toward the house while E26 tracks the action with direction.
- **Overlapped Gab choreography**: microactions happen during Rheed's Gab; a final barrier prevents clipping.
- **Quiet disappearance**: page B fades characters and performs existing cleanup without replaying Fog.

## Business Rules

1. Rheed's current line remains the only MVP Gab.
2. E33 must return to `(11,9)` before page B cleanup.
3. Every movement route introduced by the rework must wait for completion.
4. Page B must preserve the current cleanup targets and Self Switch outcomes.
5. The scene must not add a second Fog, flash, shake, `Miss`, `Blind`, `Sand`, or child sound cue.
6. The nominal target is 4.7–5.3 seconds; static validation must not claim Playtest approval.

## User Experience

The player returns from Map049, sees the group materialize, reads Rheed's introduction, notices E33 approach the house and E26 follow the movement, then sees Rheed guide the group before a quiet fade. The scene remains understandable with mute audio and reduced flash.

## High-Level Technical Constraints

- Preserve the RPG Maker MZ Map045 event schema and active VisuStella commands.
- Prefer existing engine and VisuStella event commands over plugin changes.
- Modify no global Gab parameter, plugin source, asset, database ID, or unrelated event.
- Use structured parsing, semantic anchors, a restricted diff, and a replayable writer.

## Non-Goals (Out of Scope)

- No new child dialogue in the MVP.
- No choreography for all 18 children.
- No map geometry, collision, asset, BGM asset, plugin, save-system, or skip-system change.
- No claim of final perceptual quality before human Playtest.

## Open Questions

None for implementation. Human Playtest decides whether the body-led reaction is sufficiently legible and whether the fallback variant is needed.

# Part II — Technical

## Executive Summary

Implement one semantically anchored transformation of Map045 E36. Page A retains the existing reveal and Rheed Gab, adds waited routes for E33, E26, and Rheed, applies local Gab timing overrides, and inserts `Wait For Gab Completion` only before the final hold. Page B removes the repeated Fog and its 60-frame delay while preserving opacity fade and cleanup.

The production edit must be generated by a fail-closed Node.js writer and checked by a dedicated static validator. The writer must preserve unrelated dirty-worktree content and avoid broad JSON reserialization.

## MVP Boundary

Task 1 is the complete MVP: writer, Map045 transformation, validator, fixtures, and static evidence. The spoken child and balloon-cascade variants are post-MVP and require a new approval.

## Developer Experience

- [Developer experience contract](_dx.md) — exact check, apply, validate, and failure surfaces.

## System Architecture

- **Structured writer**: locates Map045 E36 and its page anchors, computes the approved command replacement, and writes only after every precondition passes.
- **Map045 data**: owns the shipped page-A/page-B event command lists.
- **Static validator**: verifies effect count, Gab contract, waited routes, page-B fade, cleanup fingerprint, and restricted scope.
- **Fixtures**: prove idempotency and fail-closed behavior without mutating production data.

## Architectural Boundaries

- Authoring scripts may read and write only `frontend/data/Map045.json` and their own fixture/evidence directories.
- Production plugin files, `Map049.json`, `Animations.json`, and other events remain read-only dependencies.
- No new runtime package or plugin is introduced.

## Implementation Design

### Core Interfaces

No new runtime interface is introduced. The public authoring interface is the two Node.js commands frozen in `_dx.md`.

### Data Models

No new database fields, switches, variables, JSON entities, or configuration keys are introduced. Existing RPG Maker event-command objects remain the only data model. Side-table-versus-JSON is not applicable because the change adds no domain entity.

### API Endpoints

Not applicable; the feature exposes no HTTP, UDS, CLI product API, or web surface.

## Extensibility Integration Plan

Extensions, hooks, skills, MCP sidecars, plugin registries, and manifests are unaffected. The rework uses already-active VisuStella event commands.

## Agent Manageability Plan

Agents operate the change through the deterministic scripts in `_dx.md`. Both commands emit one structured JSON result and stable nonzero failures. No UI-only operation is required for static verification; human RPG Maker Playtest remains a separate perceptual gate.

## Config Lifecycle

No configuration key or global plugin parameter changes. Gab timing overrides live only in the E36 command payload.

## Testing Approach

Node fixtures cover transformation, idempotency, and precondition failures. Integration tests parse real RPG Maker JSON and exercise writer-to-validator wiring. The end-to-end static journey applies the writer to production Map045 and verifies a restricted semantic diff. Human Playtest remains pending.

## Development Sequencing

### Build Order

1. Capture E36 and protected-scope fingerprints.
2. Implement and test the fail-closed writer on fixtures.
3. Implement and test the validator.
4. Apply once to production Map045.
5. Run JSON parse, restricted diff, static validator, and syntax gates.

### Technical Dependencies

- Existing RPG Maker MZ event-command schema.
- Active `VisuMZ_4_GabWindow` and `VisuMZ_1_EventsMoveCore` commands.
- Node.js available from the repository toolchain.

## Monitoring and Observability

No runtime telemetry changes. Authoring evidence records checks, failures, file hash, and `runtime=pending_playtest`.

## Technical Considerations

### Key Decisions

- Use body language rather than a second Gab to meet the timing target.
- Overlap choreography with Gab retention, then synchronize only at the final boundary.
- Use a manual short Rheed route instead of non-blocking pathfinding to `(5,5)`.
- Remove repeated Fog from page B to give entry and exit distinct meaning.

### Known Risks

- `<center>` tags may affect Gab retention count; Playtest must measure the actual duration.
- E33's step may read as navigation; the approved fallback is the three-child visual cascade.
- The existing dirty Map045 can contain concurrent user changes; semantic preconditions and restricted writes are mandatory.

## Safety Invariants

1. The writer must not write when any semantic precondition fails.
2. No event other than E36 may change.
3. The cleanup fingerprint must remain identical.
4. A second writer run must not change the file.
5. Static evidence must report Playtest as pending.
